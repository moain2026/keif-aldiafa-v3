**ملاحظات Schema (من CRITICAL-SEO-AUDIT.md في المستودع — تحققت منها):**

- `ImageObject` بلا width/height — تحسين P2.
- `PostalAddress` بدولة فقط (قرار مقصود للتغطية الوطنية) — موثّق ومقبول.

## 2) مشاكل مرصودة بالأرقام (تدخل فجوات اللفة)

1. **وزن HTML الأولي**: الرئيسية **264KB**، offerings **262KB**، portfolio **258KB**، services **205KB** (وسيط الموقع 119KB). هذا HTML فقط — قبل JS. سبب مباشر لبطء LCP/TBT ويمس هدف المادة 8.
2. **عناوين أطول من 65 حرفاً (تُقص في SERP)**: 5 صفحات — `sababin-qahwa-makkah (66)، sababin-qahwa-madinah (70)، qahwajiin-madinah (68)، diyafa-munasabat-makkah (67)، diyafa-munasabat-madinah (71)`. إصلاح سهل: صيغة أقصر لمدن الأسماء الطويلة.
3. **محتوى نصي رفيع**: وسيط الموقع 683 كلمة؛ الرئيسية **470 كلمة** فقط؛ portfolio 278، locations 291، contact 327. المنافس الأقوى (al-mostakbl.com) صفحته ~231KB محتوى فعلي. خطر «قيمة مضافة منخفضة» على صفحات المدن المتشابهة قالبياً.
4. **alt المعرض قالبي مكرر** (`PortfolioClient.tsx:343`): 80+ صورة بنفس النص + رقم — أقوى إشارة صور مهدورة (P0 في تدقيق المستودع، لم يُنفّذ).

## 3) خريطة الكلمات المفتاحية الحالية (Keyword Map)

البنية الحالية 40 URL = رئيسية + 7 صفحات عامة + 8 صفحات مواقع عربية + **24 صفحة هبوط SEO** (8 مدن × 3 خدمات):

| العنقود | النمط | الصفحات | الكلمة الأساسية |
|---|---|---|---|
| قهوجيين | `/qahwajiin-{city}` | 8 | «قهوجيين {مدينة}» + حجز/VIP |
| صبابين قهوة | `/sababin-qahwa-{city}` | 8 | «صبابين قهوة {مدينة}» |
| ضيافة مناسبات | `/diyafa-munasabat-{city}` | 8 | «ضيافة مناسبات {مدينة}» |
| مواقع (عربي) | `/locations/{المدينة}` | 8 | استعلامات الموقع الجغرافي |
| الرئيسية | `/` | 1 | «قهوجيين وصبابين قهوة السعودية» (العلامة + العام) |

المدن: الرياض، جدة، مكة، المدينة، الدمام، الطائف، أبها، ينبع.

**الرئيسية اليوم تحمل الاستعلام الوطني العام** («قهوجيين وصبابين قهوة لضيافة فاخرة في السعودية») وتوزّع سلطتها عبر **33 رابطاً داخلياً** لصفحات المدن/المواقع (من أصل 59 رابطاً داخلياً). هذه هي الوظيفة السلطوية الأهم للرئيسية.

## 4) مخاطر إعادة بناء الرئيسية على الترتيب — قائمة إلزامية للفة 2+

أي تنفيذ يمس الرئيسية يجب أن يجتاز هذه القائمة قبل الدمج (أُدرجها في بوابة مراجع الكود):

| # | الخطر | القاعدة الملزمة |
|---|---|---|
| R1 | **فقدان الروابط الداخلية للمدن** — الرئيسية تغذي 24 صفحة هبوط بـ33 رابطاً | الرئيسية الجديدة تحتفظ بروابط **كل** صفحات المدن الـ24 + `/locations` (نصية زاحفة في HTML الأولي، ليست JS-only) |
| R2 | تغيير/فقدان `title`, `description`, `canonical` للرئيسية | تُنقل كما هي أو تُحسَّن بقرار موثق في docs/decisions/ — لا تُفقد أبداً |
| R3 | فقدان كتل JSON-LD (خاصة `CateringService`, `Organization`, `WebSite`) | كل الأنواع الحالية تبقى وتجتاز الـparsing؛ فحص آلي كل دورة |
| R4 | كسر H1 الوحيد أو تحويله لعنوان علامة بلا كلمات خدمية | H1 واحد يتضمن «قهوجيين/صبابين قهوة» + إشارة جغرافية |
| R5 | حذف المحتوى النصي القابل للفهرسة (الرئيسية 470 كلمة أصلاً — رفيعة) | الرئيسية الجديدة **لا تقل** عن الحالي نصياً؛ المستهدف يُثبّت في §4 من PLAN.md |
| R6 | تغيير مسارات الصور/OG image | `og-cover` وصور الـCDN تبقى صالحة؛ فحص 200 لكل src |
| R7 | إدخال CLS عبر خطوط/صور بلا أبعاد | width/height أو aspect-ratio لكل وسائط above-the-fold |
| R8 | تضخيم HTML أكثر (264KB أصلاً) | هدف: HTML الأولي للرئيسية **≤150KB** (يُقر في §4 PLAN.md) |
| R9 | المساس بصفحات المدن (المادة 10 تمنع) | صفر تعديل على الـ24 صفحة إلا إصلاح alt/العناوين الطويلة كمهمة منفصلة |
| R10 | إسقاط robots/sitemaps أثناء إعادة الهيكلة | `robots.ts`, `sitemap.ts`, `image-sitemap`, `sitemap_index` تبقى وتُختبر بعد كل build |

**فحص SEO الآلي لكل دورة (سأنفذه بنفسي):** زحف الـ40 URL + تحقق canonical/title/H1/JSON-LD + عدّ روابط المدن على الرئيسية ≥25 + مقارنة وزن HTML — والنتيجة تُرفق في docs/evidence/seo/loop-N.

## 5) مقترحات للعقد الرقمي (§4 PLAN.md) — من زاوية SEO

- الرئيسية: ≥700 كلمة قابلة للفهرسة في HTML الأولي (فوق الحالي 470، دون حشو).
- HTML أولي ≤150KB للرئيسية.
- روابط داخلية نصية: كل صفحات المدن الـ24 + الخدمات الرئيسية.
- H1 خدمي جغرافي واحد + هيكل H2 يغطي: الخدمات، المدن، لماذا نحن (ثقة)، الأعمال، التواصل.
- إصلاحان سريعان مستقلان عن إعادة البناء: العناوين الخمسة الطويلة + alt الفريد للمعرض (P0 الجاهز في imageCatalog).
