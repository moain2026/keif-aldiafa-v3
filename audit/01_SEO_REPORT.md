## 0) نتيجة التحقق الفوري: is-crawlable ✅ لا مشكلة في الإنتاج

**فحص حي:**
```
curl -sI https://keifaldiafa.com/  →  HTTP/2 200 + x-robots-tag: all
```
الـ `noindex` **محلي فقط** — `next.config` يضبط `X-Robots-Tag: noindex, nofollow` عندما `VERCEL_ENV !== 'production'` (سطر 82). الإنتاج الحي يرسل `all`. **لا إجراء مطلوب**، فقط انتبه: أي preview/staging deployment سيبقى noindex (وهذا صحيح ومقصود). درجة SEO 69 في Lighthouse المحلي سببها هذا الهيدر فقط — الدرجة الحقيقية للإنتاج أعلى.

## 1) On-Page: العناوين والـ Headings (أكبر فجوة تقنية) 🔴

### 1.1 كلمة "قهوجي/قهوجية" غير موجودة إطلاقاً في المحتوى المرئي 🔴
**المشكلة:** فحص الكود المرئي (Client components):
| الكلمة | مرات الظهور في المحتوى المرئي |
|--------|------|
| قهوجي / قهوجية | **0** ❌ |
| صبابين | 6 |
| صبابات | 10 |
| مباشرين | 5 |

"قهوجي/قهوجيين" هي **الكلمة الأعلى بحثاً** في هذا السوق (المنافسون المتصدرون كلهم يستخدمونها: qahwajie.com, kahwgy.com, qahwajiin.com). وجودها في meta keywords فقط = صفر قيمة (جوجل تتجاهل keywords meta منذ 2009).

**الحل:** إدخالها طبيعياً في H1/H2 والفقرات: hero الرئيسية، وصف خدمة الصبابين في /services، صفحة عن، والـ FAQ.
```tsx
// HomePageClient.tsx — فقرة hero الحالية:
"...أفضل طاقم صبابين وصبابات زواجات ومباشرين بزي فاخر..."
// المقترح:
"...أفضل طاقم قهوجيين وصبابين قهوة، صبابات ومباشرات زواجات، وقهوجية بزي فاخر..."
```
**الأولوية: 🔴 P0** — بدون الكلمة لن تترتب عليها مهما فعلت.

### 1.2 كل H1 في الموقع "شاعري" بلا كلمات مفتاحية 🔴
**المشكلة (من الكود الفعلي):**
| الصفحة | H1 الحالي | التقييم |
|--------|-----------|---------|
| / | `كيف الضيافة` | اسم العلامة فقط — يهدر أهم عنصر on-page |
| /services | `باقة متكاملة من الضيافة الفاخرة` | لا "قهوجية" ولا "صبابين" |
| /offerings | `تشكيلة فاخرة من الضيافة الأصيلة` | عام جداً |
| /portfolio | `توثيق للحظات الفخامة والتميز` | لا يصف شيئاً قابلاً للبحث |
| /about | `من نحن في كيف الضيافة` | مقبول |
| /contact | `نسعد بخدمتكم` | لا كلمات |

**الحل (اقتراحات جاهزة تحافظ على الفخامة):**
```
/          → كيف الضيافة | قهوجيين وصبابين قهوة لضيافة فاخرة في السعودية
/services  → خدمات قهوجية وصبابين وصبابات — ضيافة VIP لكل المناسبات
/offerings → تقديمات الضيافة: قهوة سعودية، شاي، حلويات وتمور فاخرة
/portfolio → معرض أعمالنا: +500 مناسبة ضيافة في مدن المملكة
/contact   → احجز قهوجيين وطاقم ضيافة لمناسبتك — استشارة مجانية
```
ملاحظة تنفيذية: يمكن الإبقاء على الجملة الشاعرية كسطر ثانٍ `<p>` تحت H1 — لا تضحِّ بالتصميم.
**الأولوية: 🔴 P0**

### 1.3 Titles الداخلية عامة بلا كلمات/مدن 🟠
**المشكلة:** الحي الآن: `<title>خدماتنا | كيف الضيافة</title>` — "خدماتنا" لا يبحث عنها أحد.
**الحل:** في كل `page.tsx` مرّر title غنياً لـ `generatePageMetadata`:
```ts
// services/page.tsx
title: "قهوجيين وصبابين قهوة — خدمات ضيافة فاخرة"
// → يصبح: قهوجيين وصبابين قهوة — خدمات ضيافة فاخرة | كيف الضيافة
// offerings: "تقديمات ضيافة: قهوة سعودية وشاي وحلويات فاخرة"
// portfolio: "معرض أعمال الضيافة — +500 مناسبة ناجحة"
// contact:   "احجز طاقم ضيافة — واتساب مباشر واستشارة مجانية"
```
انتبه لطول العنوان (≤60 حرفاً تقريباً قبل القص).
**الأولوية: 🟠 P1**

### 1.4 خطأ إملائي في metadata صفحة الخدمات: "صباح قهوة" 🔴 (سريع الإصلاح)
**المشكلة:** `services/page.tsx` — الوصف والكلمات فيهما **"صباح قهوة سعودية"** (مرتين في description + مرة في keywords + مرة في serviceSchema). الصحيح "صبّاب قهوة / صبابين قهوة". هذا نص يظهر في نتائج البحث فعلياً.
**الحل:** تصحيح إلى "صبابين قهوة سعودية" في المواضع الأربعة.
**الأولوية: 🔴 P0** (دقيقتان)

### 1.5 هرمية Headings: مشاكل محددة 🟡
من grep الفعلي على `<h1-h6>`:
1. **ServicesClient سطرا 168 و179:** نفس `service.title` يُرسم `<h2>` مرتين (نسخة موبايل + ديسكتوب) → headings مكررة في DOM. الحل: أبقِ واحدة `<h2>` وحوّل الثانية لـ `<p aria-hidden>` أو استخدم عنصراً واحداً responsive.
2. **PortfolioClient: لا يوجد أي H2** — من H1 مباشرة إلى الصور. أضف H2 لكل فئة (أعراس، فعاليات شركات، معدات...) — يفيد أيضاً اقتباس AI Overviews.
3. **التسميات الزخرفية `✦ خدماتنا ✦` تُرسم `<p>`** قبل H1 — سليم، أبقِها كذلك.
4. **ContactClient سطر 40:** `<h2>شكراً لتواصلك!</h2>` يظهر شرطياً بعد الإرسال — سليم لكن الأفضل `role="status"` بدل heading.
5. الرئيسية: H1 → H2 (أقسام) → H3 (بطاقات) ✅ سليمة بنيوياً — تحتاج فقط إثراء نصوص H2 (مثلاً "ضيافة مناسبات VIP نصنع فيها الفرق" ✅ جيدة).
**الأولوية: 🟡 P2**

### 1.6 رابط داخلي غير قانوني في الـ hero 🟡
**المشكلة:** `HomePageClient.tsx` سطر 191: `<Link href="services">` — بدون `/` بادئة (نسبي). يعمل من الجذر لكنه هش وغير قانوني.
**الحل:** `href="/services"`.
**الأولوية: 🟡 P2** (ثوانٍ)

### 1.7 المحتوى النصي رقيق جداً (Thin Content) 🟠
**المشكلة:** الرئيسية = hero + 4 بطاقات "لماذا نحن" + شركاء. لا يوجد قسم نصي يشرح الخدمات/المدن/الأسعار. المنافسون المتصدرون (qahwajie.com) لديهم 800+ كلمة لكل صفحة. صفحات المحتوى الحالية تعتمد على عناوين قصيرة وبطاقات.
**الحل (بدون تخريب التصميم):**
- أضف قسماً في أسفل الرئيسية: "خدمات الضيافة في مدن المملكة" — فقرة 150-250 كلمة تذكر (قهوجيين، صبابين، صبابات، الرياض، جدة، مكة، الدمام...) + روابط لصفحات المدن القادمة (§5).
- انقل الـ FAQ الأربعة الموجودة في schema فقط إلى **محتوى مرئي** في الرئيسية (accordion) — حالياً FAQPage schema موجود بلا محتوى مرئي مطابق = مخالفة إرشادات جوجل للبيانات المنظمة (يجب أن تطابق المحتوى المرئي) وقد تُحتسب spammy structured data.
**الأولوية: 🟠 P1** — مطابقة الـ FAQ المرئي تحديداً 🔴.

## 2) Schema: الموجود قوي، الناقص محدّد

الموجود حياً (فحص فعلي): Organization ×1، LocalBusiness (ProfessionalService+FoodService)، WebSite، BreadcrumbList، FAQPage (4 أسئلة)، WebPage، Service. البنية مركزية في `lib/schema.ts` ✅ ممتازة.

### 2.1 لا يوجد AggregateRating / Review — أكبر نقص 🟠
**المشكلة:** نجوم التقييم من أهم ما تبقى من rich results في 2026 (بعد إلغاء FAQ rich results في مايو 2026 — انظر 04_STRATEGY §5). الموقع يدّعي "+500 مناسبة" بلا أي تقييم منظم.
**الحل:** اجمع تقييمات حقيقية (Google Business Profile أولاً)، ثم أضف على LocalBusiness:
```ts
// lib/schema.ts — داخل generateLocalBusinessSchema()
aggregateRating: {
  "@type": "AggregateRating",
  ratingValue: "4.9",
  reviewCount: "137",       // أرقام حقيقية فقط — جوجل تعاقب المفبركة
},
review: [{
  "@type": "Review",
  author: { "@type": "Person", name: "عبدالله الحربي" },
  reviewRating: { "@type": "Rating", ratingValue: "5" },
  reviewBody: "طاقم قهوجيين محترف...",
  datePublished: "2026-05-14",
}],
```
⚠️ الشرط: التقييمات يجب أن تكون **مرئية على الصفحة** (قسم "آراء عملائنا") — لا schema بلا محتوى.
**الأولوية: 🟠 P1** (بعد جمع تقييمات حقيقية)

### 2.2 نوع LocalBusiness: `FoodService` ليس الأدق 🟡
**المشكلة:** `["ProfessionalService","FoodService"]` — `FoodService` نوع Intangible/service وليس LocalBusiness subtype، وجوجل تفضّل أنواع LocalBusiness المعروفة.
**الحل:** الأنسب لهذا النشاط: **`Caterer`** (نوع LocalBusiness رسمي مدعوم في وثيقة جوجل):
```ts
"@type": ["Caterer", "ProfessionalService"],
```
وأضف حقولاً تقوّي الكيان:
```ts
foundingDate: "2016",
slogan: "ضيافة فاخرة تليق بضيوفكم",
knowsAbout: ["القهوة السعودية", "ضيافة الأعراس", "قهوجيين", "صبابين وصبابات"],
hasOfferCatalog: {
  "@type": "OfferCatalog",
  name: "خدمات الضيافة",
  itemListElement: [
    { "@type": "Offer", itemOffered: { "@type": "Service", name: "قهوجيين وصبابين قهوة" } },
    { "@type": "Offer", itemOffered: { "@type": "Service", name: "صبابات ومباشرات" } },
    { "@type": "Offer", itemOffered: { "@type": "Service", name: "تجهيز طاولات استقبال" } },
  ],
},
```
**الأولوية: 🟡 P2**

### 2.3 Service schema واحد عام لكل الصفحة 🟡
**المشكلة:** `/services` فيه Service واحد اسمه "خدمات الضيافة الفاخرة" بينما الصفحة تعرض 10+ خدمات فعلية (مضيفون، صبابين، سقاء زمزم، خطاط، بوفيه...).
**الحل:** ولّد مصفوفة Service من نفس بيانات `services` array في ServicesClient (انقل البيانات لملف مشترك `lib/services-data.ts` يستورده السيرفر والعميل):
```ts
services.map(s => generateServiceSchema({ name: s.title, description: s.description, url: `${SITE_URL}/services#${s.id}` }))
```
**الأولوية: 🟡 P2**

### 2.4 FAQPage: أبقِه لكن طابقه مع المرئي 🔴
جوجل ألغت FAQ **rich results** (مايو 2026) لكن الـ schema يبقى مفيداً لـ AI Overviews. المشكلة الحالية ليست وجوده بل أن الأسئلة **غير مرئية** على الصفحة (§1.7). أضف الـ accordion المرئي، ووسّع لاحقاً لأسئلة المدن ("كم سعر القهوجي في الرياض؟" — نمط الاقتباس المفضل لـ AI Overviews).
**الأولوية: 🔴 P0** (المطابقة) / 🟡 (التوسعة)

### 2.5 Breadcrumb مزدوج: JSON-LD + Microdata 🟡
**المشكلة:** `Breadcrumbs.tsx` يحمل microdata (`itemScope itemType="https://schema.org/BreadcrumbList"`) وكل page.tsx يحقن JSON-LD BreadcrumbList — ازدواجية قد تسبب تعارضاً (خاصة أن microdata فيه `itemProp="item"` على `<Link>` بدون `content` URL مطلق).
**الحل:** احذف microdata attributes من Breadcrumbs.tsx واكتفِ بـ JSON-LD (توصية جوجل: صيغة واحدة).
كذلك: breadcrumb الرئيسية (`page.tsx`) عنصر واحد فقط "الرئيسية" — بلا فائدة، احذفه.
**الأولوية: 🟡 P2**

### 2.6 sameAs ناقص TikTok 🟡
الفوتر فيه رابط `tiktok.com/@keifaldiafa` لكن schema `sameAs` يحوي إنستقرام + wa.me فقط. أضف تيك توك (وأزل wa.me من sameAs — ليس ملفاً اجتماعياً، مكانه `contactPoint`). أضف أيضاً رابط Google Business Profile عند إنشائه، وحساب X إن وُجد (@keifdiafa مذكور في twitter meta — تحقق أنه موجود فعلاً).
**الأولوية: 🟡 P2**

## 3) E-E-A-T التقني

### 3.1 صفحة "من نحن" رقيقة 🟠
**الموجود:** فقرة "قصتنا" (منذ 2016، +500 مناسبة) + 4 قيم. **الناقص لإشارات E-E-A-T 2026:**
- **رقم السجل التجاري / معروف** (أقوى إشارة شرعية للسوق السعودي) — أضفه في الفوتر وصفحة عن.
- أسماء/صور المؤسس أو مدير العمليات (حتى بالاسم الأول + المسمى).
- أرقام موثقة: عدد الكوادر، المدن المخدومة، شعارات عملاء (موجودة في PartnersMarquee — اربطها بنص "من عملائنا: ...").
- شهادات/تراخيص (بلدية، سلامة غذائية إن وجدت).
**الأولوية: 🟠 P1**

### 3.2 NAP وقنوات التواصل 🟡
- البريد `keifaldiafa@gmail.com` — أنشئ `info@keifaldiafa.com` (Gmail المجاني إشارة ضعف ثقة، والمنافسة على أعمال VIP/حكومية).
- لا يوجد عنوان مادي في الموقع أو schema (address = SA فقط). كنشاط Service-Area هذا مقبول لجوجل، لكن لإنشاء **Google Business Profile** (حجر أساس الترتيب المحلي — انظر 04_STRATEGY §6) ستحتاج عنواناً للتحقق ثم إخفاءه (SAB mode).
- وحّد صيغة الهاتف في كل مكان: `+966 50 825 2134`.
**الأولوية: 🟡 P2** (GBP نفسه 🔴 لكنه خارج الكود)

### 3.3 author/publisher
لا مدونة حالياً، فلا حاجة لـ author schema الآن. عند إطلاق المدونة (خطة الكلمات المعلوماتية في 04_STRATEGY §ج-3): كل مقال `Article` + `author: Person` باسم حقيقي + `publisher` = Organization الحالية (جاهزة). WebSite publisher موجود ✅.

## 4) توزيع الكلمات المفتاحية العربية (حالة الكود)

| الكلمة المستهدفة | Meta | H1/H2 مرئي | نص مرئي | الفجوة |
|---|---|---|---|---|
| قهوجي / قهوجيين | ✅ | ❌ | ❌ **0 مرة** | 🔴 أضفها (1.1) |
| صبابين قهوة | ✅ | ❌ | ✅ 6 | H1/H2 |
| صبابات / مباشرات | ✅ | ❌ | ✅ 10/5 | H1/H2 |
| قهوجية (مؤنث/جمع عامي) | ✅ | ❌ | ❌ 0 | 🔴 |
| ضيافة + [مدينة] | الرياض فقط في meta | ❌ | ❌ (المدن مذكورة في FAQ schema غير المرئي فقط) | 🔴 صفحات مدن (§5) |
| سعر/أسعار القهوجيين | ❌ | ❌ | ❌ | 🟠 قسم أسعار/FAQ — أعلى نية شرائية |
| تأجير دلال/معدات ضيافة | جزئي | ❌ | جزئي (offerings) | 🟡 |

**قاعدة تنفيذية:** كل صفحة تستهدف عنقوداً واحداً: الرئيسية (العلامة + قهوجيين السعودية)، /services (الخدمات + الطاقم)، /offerings (التقديمات + التأجير)، صفحات المدن (خدمة×مدينة). لا تحشُ كل الكلمات في كل صفحة — أكل ذاتي (cannibalization).

## 5) Local SEO: هيكل صفحات المدن (routes) 🟠 — الأثر الأعلى على الترتيب

المنافسون يتصدرون بصفحة لكل مدينة (04_STRATEGY §ب). المقترح التقني لـ Next.js App Router:

### 5.1 البنية
```
src/app/locations/
├── page.tsx                    # فهرس "مناطق التغطية" — يربط كل المدن
└── [city]/
    └── page.tsx                # SSG عبر generateStaticParams
src/lib/cities-data.ts          # مصدر البيانات الوحيد
```
```ts
// lib/cities-data.ts
export const CITIES = [
  { slug: "riyadh",  name: "الرياض",          districts: ["حي الملقا","حي النرجس","حي حطين"], intro: "..." },
  { slug: "jeddah",  name: "جدة",             districts: [...], intro: "..." },
  { slug: "makkah",  name: "مكة المكرمة", ... },
  { slug: "madinah", name: "المدينة المنورة", ... },
  { slug: "dammam",  name: "الدمام والخبر", ... },
  { slug: "taif",    name: "الطائف", ... },
  { slug: "abha",    name: "أبها وخميس مشيط", ... },
  { slug: "yanbu",   name: "ينبع", ... },
  { slug: "tabuk",   name: "تبوك", ... },
] as const;
```
```tsx
// app/locations/[city]/page.tsx
export function generateStaticParams() { return CITIES.map(c => ({ city: c.slug })); }
export function generateMetadata({ params }): Metadata {
  const c = getCity(params.city);
  return generatePageMetadata({
    title: `قهوجيين وصبابين قهوة في ${c.name} — ضيافة فاخرة`,
    description: `احجز قهوجيين وصبابات في ${c.name}: قهوة سعودية، طاقم بزي فاخر، تغطية ${c.districts.join("، ")}. واتساب فوري.`,
    path: `/locations/${c.slug}`,
  });
}
```
**Slugs إنجليزية** (`/locations/riyadh`) وليست عربية — أسهل مشاركةً وأنظف في التقارير؛ العربية في URL ميزة طفيفة لا تستحق مشاكل الترميز (المنافس thawq-rafeea يعاني URLs عربية طويلة).

### 5.2 شروط محتوى صفحة المدينة (وإلا صارت doorway pages وتُعاقب)
- 400-700 كلمة **فريدة لكل مدينة**: أحياء التغطية، قاعات/فنادق المدينة المعروفة، صور من مناسبات فعلية فيها (عندك 388 صورة — صنّفها بالمدينة)، شهادة عميل من المدينة.
- H1: `قهوجيين وصبابين قهوة في {المدينة}` | H2s: خدماتنا في {المدينة} / أحياء التغطية / أسئلة شائعة / آراء عملاء.
- FAQ خاص بالمدينة (سعر، حجز مسبق، مناطق التغطية) — مرئي + schema.
- Schema لكل صفحة: `Service` (areaServed = City) + `BreadcrumbList` + FAQ. **لا** تكرر LocalBusiness كاملاً بعنوان مختلف لكل مدينة (كيان واحد).
- أطلقها على دفعات: ابدأ الرياض + جدة + الدمام (أعلى حجم بحث)، قِس، ثم توسّع.

### 5.3 الربط

**الأولوية: 🟠 P1-P2** (أعلى أثر على الترتيب على الإطلاق)

## 6) Internal Linking / Breadcrumbs / Sitemap

### 6.1 الربط الداخلي شبه معدوم في المحتوى 🟠
**المشكلة:** جسم الرئيسية فيه رابطان فقط (واتساب + /services). لا روابط سياقية بين الصفحات (services ↔ offerings ↔ portfolio).
**الحل:**
- بطاقات "لماذا نحن": "تقديمات فاخرة" → رابط /offerings، "تغطية المملكة" → /locations.
- أسفل /services: "شاهد تقديماتنا" + "تصفح أعمالنا". أسفل /offerings: رابط /services.
- نصوص الروابط (anchor text) بكلمات وصفية: "خدمات القهوجيين والصبابين" وليس "اضغط هنا".
**الأولوية: 🟠 P1**

```ts
{ path: "/services", lastModified: "2026-06-20", ... }
```
وأضف صفحات المدن عند إنشائها. (اختياري ⚪: image sitemap لصور /portfolio الـ388 مع تسميات مدن — يدعم Google Images وحركة بحث الصور عن "ضيافة زواج".)
**الأولوية: 🟡 P2**

## 7) نقاط تقنية متفرقة وُجدت أثناء الفحص

1. 🟠 **CLS /services = 1.405** (من AUDIT_DATA) — ليس ملف SEO بحت لكنه كاسر تعادل ترتيب (CWV). السبب المرجح: بطاقات الخدمات/الصور بلا أبعاد محجوزة + دخول motion. أعطِ كل صورة `width/height` أو `aspect-ratio` ثابت، وثبّت ارتفاع الشبكة قبل hydration. LCP 4.4-5.6s: أضف `preload` لبوستر الـ hero و`fetchpriority="high"`، وأجّل تحميل الفيديو (`preload="none"` + تشغيل بعد onLoad).
2. 🟡 **alt نصوص الصور قليلة** (grep: services=6، offerings=2، portfolio=2 مواضع alt لمئات الصور المعروضة عبر مكونات). PortfolioClient يستخدم قالب alt جيداً (`seoAltMapping`) ✅ — طبّق نفس النمط في offerings (`alt={item.name + " — تقديمات كيف الضيافة"}`) وتأكد أن ImageWithFallback يمرر alt دائماً.
3. 🟡 **عنوان الرئيسية مع الـ template:** layout يعرّف `template: "%s | كيف الضيافة"` وpage.tsx للرئيسية يمرر title نصياً يبدأ بـ"كيف الضيافة | ..." — إن ظهر مستقبلاً "… | كيف الضيافة" مكرراً، استخدم `title: { absolute: "..." }` في الرئيسية.
4. ⚪ CSP فيه `unsafe-eval/unsafe-inline` — ليس عامل ترتيب، لكن نظّفه لاحقاً (nonce لـ GTM).
5. ⚪ `alternates.languages` يعرّف ar-SA فقط — سليم لموقع أحادي اللغة؛ لا تضف hreflang إنجليزية بلا صفحات إنجليزية فعلية.
